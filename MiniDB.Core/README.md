# MiniDB.Core

Независимое ядро MiniDB, вариант 01. Не зависит от WPF, ASP.NET Core или файлового хранилища. Не использует сторонние пакеты.

| Класс / интерфейс | Ответственность |
| --- | --- |
| Database | Имя базы, коллекция таблиц, добавление, удаление и получение таблицы по имени. |
| Table | Имя, схема и строки; добавление колонок, добавление и редактирование строк, получение колонки и строк. |
| Column | Неизменяемые имя колонки и её IDataType. |
| Row | Типизированные значения по именам колонок; чтение и изменение ячеек с проверкой типа. |
| Color | Неизменяемые Red, Green, Blue, каждая в диапазоне 0..255. |
| ColorInterval | Неизменяемые MinColor и MaxColor, упорядоченные по каждой RGB-компоненте. |
| IDataType | Общий контракт Name, Validate(string?), ValidateValue(object?), Parse(string). |
| DataType<T> | Общий разбор текста и проверка CLR-типа сохранённого значения; единые ошибки преобразования. |
| IntegerType | `integer`: 32-битный int, включая отрицательные числа. |
| RealType | `real`: конечный double с InvariantCulture; точка, допускается экспоненциальная запись. |
| CharType | `char`: ровно один C# char (UTF-16 code unit). |
| StringType | `string`: любая ненулевая строка, включая пустую, без обрезания пробелов. |
| ColorType | `color`: формат RGB(r, g, b); общий разбор RGB и проверка диапазонов. |
| ColorIntervalType | `colorInvl`: формат [RGB(...); RGB(...)]; переиспользует разбор ColorType и проверяет порядок границ. |
| TableValidator | Проверка имени таблицы, непустой схемы, имён и уникальности колонок, наличия IDataType с непустым именем. |
| RowValidator | Проверка типизированной Row относительно схемы выбранной Table, без повторного разбора текста. |
| SearchService | Индивидуальная операция варианта 01: поиск строк по шаблону в выбранной колонке. |

## Пример

```csharp
using MiniDB.Core.DataTypes;
using MiniDB.Core.Models;

var database = new Database("Demo");
var table = new Table("Items");
table.AddColumn(new Column("Id", new IntegerType()));
table.AddColumn(new Column("Color", new ColorType()));
database.AddTable(table);

var row = table.AddRow(new[] { "1", "RGB(255, 0, 0)" });
var color = (Color)row.GetValue("Color");
row.SetValue("Color", "RGB(0, 255, 0)");
table.EditRow(0, new[] { "2", "RGB(0, 0, 255)" });
```

## Архитектурные решения

- Самих UML-файлов в рабочей папке нет; реализация следует списку моделей и методов из задания. Дополнительные детали реализации описаны ниже.
- Общий базовый класс DataType<T> устраняет расхождения между Validate и Parse. Внешний контракт остаётся IDataType; Parse возвращает object с конкретным типом значения.
- Row получает схему при создании и хранит Values как словарь `имя колонки -> типизированное значение`. SetValue принимает текст и проверяет его через IDataType колонки. Это защищает таблицу от неверных типов при прямом изменении Row.
- AddRow и EditRow принимают текстовые значения в порядке Columns. Количество значений должно точно совпадать с количеством колонок. EditRow использует индекс с нуля и сохраняет тот же объект Row.
- Новая строка добавляется, а редактирование существующей применяется только после успешного разбора всех значений. Ошибка оставляет прежнее состояние.
- Колонки можно добавлять только до появления строк. Причина: значения по умолчанию и миграция схемы ещё не определены. Это ограничение объявлено перед реализацией.
- Коллекции доступны только для чтения; все изменения идут через методы моделей. Имена, Column, Color и ColorInterval неизменяемы.
- Имена не могут быть пустыми или состоять только из пробелов. Дубликаты таблиц и колонок запрещены; сравнение имён регистрозависимое (Ordinal), без автоматического обрезания пробелов.
- RGB-парсер общий для обоих цветовых типов; диапазон компоненты определяется в одном методе Color.IsValidComponent. Порядок границ определяется в ColorInterval.IsOrdered. Конструкторы моделей также защищают их корректность при прямом создании.
- RGB записывается с заглавными буквами `RGB`; вокруг значений, цветов и интервала допускаются пробельные символы.
- RealType отклоняет NaN, бесконечности и переполнение. CharType представляет C# char; emoji из двух UTF-16 code units не считается одним char. Null не является значением ни одного типа; пустая строка допустима для StringType.
- GetRows возвращает все строки. Поиск выполняется отдельно через SearchService.

## Валидаторы

TableValidator предоставляет `Validate(Table)`, `ValidateTableName(string)` и `ValidateColumns(IEnumerable<Column>)`. Последние два метода позволяют проверить имя или схему до создания таблицы. Это также позволяет проверить дубликаты, которые Table.AddColumn уже запрещает. Имена сравниваются через StringComparer.Ordinal. IDataType должен быть задан и иметь непустое имя; проверка не ограничивает расширения списка типов конкретными классами.

RowValidator предоставляет `Validate(Table, Row)`. Он сначала проверяет схему таблицы, затем неизвестные имена, отсутствие обязательных значений, соответствие типов и количество значений. Row может быть создана отдельно с другой схемой; валидатор проверяет её относительно целевой таблицы. Возвращаемый тип методов — void: успешное завершение означает корректность, ошибочные данные вызывают ArgumentException, null-аргументы — ArgumentNullException.

Уточнение контракта IDataType, объяснённое перед реализацией: добавлен `ValidateValue(object?)`. Причина — значения Row уже типизированы, и преобразование их в текст для повторного парсинга могло бы скрыть неправильный CLR-тип. Общая реализация в DataType<T> проверяет тип значения; RealType дополнительно проверяет конечность double. Для Color и ColorInterval корректность обеспечивают неизменяемые модели и их конструкторы. RowValidator не дублирует парсеры и не вызывает Parse для сохранённых значений.

Валидаторы самостоятельные, не связаны с UI, API или хранением и не меняют проверяемые объекты. Защитные проверки существующих моделей сохранены.

## Индивидуальная операция: поиск по шаблону

Сигнатура: `IReadOnlyList<Row> SearchService.Search(Table table, string columnName, string pattern)`.

- Для StringType и CharType только `*` означает произвольную последовательность символов, включая пустую и переносы строк. Сопоставляется всё значение, с учётом регистра. Пустой шаблон подходит только пустой строке; пробелы шаблона сохраняются.
- Все остальные символы буквальные: `?`, `.`, скобки и другие знаки не являются дополнительными wildcard-операторами.
- Шаблон разбивается по `*`; буквальные части ищутся по порядку через Ordinal-сравнение. Первая и последняя части закреплены на границах значения, части не перекрываются. Разбиение выполняется один раз на запрос.
- Для integer, real, color и colorInvl шаблон один раз преобразуется через IDataType.Parse, после чего сравниваются типизированные значения. Для Color и ColorInterval используется равенство значений record. Числа сравниваются точно, без допуска или округления.
- Проверка нетекстового шаблона происходит даже для таблицы без строк. Неверный шаблон вызывает FormatException; null-аргументы — ArgumentNullException; неизвестная колонка — KeyNotFoundException; пустое имя колонки — ArgumentException.
- Поиск не меняет Table или Row. Возвращается готовая коллекция только для чтения, сохраняющая порядок строк. Это снимок списка совпадений, содержащий ссылки на существующие Row, а не копии строк. Последующее добавление строк в таблицу не меняет состав результата.

```csharp
using MiniDB.Core.Search;
using MiniDB.Core.Validation;

var names = new Table("Names");
names.AddColumn(new Column("Name", new StringType()));
names.AddRow(new[] { "Dan" });
names.AddRow(new[] { "Daniel" });
names.AddRow(new[] { "Other" });

new TableValidator().Validate(names);
new RowValidator().Validate(names, names.Rows[0]);
var found = new SearchService().Search(names, "Name", "Dan*"); // Dan, Daniel
```

Полных UML-файлов в папке проекта по-прежнему нет. Добавлены требуемые самостоятельные сервисы и один метод IDataType для типизированной проверки; структура Database/Table/Column/Row не менялась.

## Ошибки

- Validate возвращает false для неверного текста и null.
- Parse выбрасывает FormatException для неверного текста, ArgumentNullException для null.
- Неизвестное имя таблицы или колонки: KeyNotFoundException. RemoveTable возвращает false, если таблицы нет.
- Неверное имя, дубликат или количество значений: ArgumentException. Неверный индекс строки или RGB-компонента при прямом создании: ArgumentOutOfRangeException.
- Изменение схемы заполненной таблицы или добавление строки без колонок: InvalidOperationException.
